# SIGNAL SNAKE — Stage 02: NOISE removal + Nokia UI

## Запуск

```sh
python3 -m http.server 8771 --bind 127.0.0.1
```

- Nokia UI: http://127.0.0.1:8771/snake.html
- Минимальный Functional Core Stage 01: http://127.0.0.1:8771/snake-core.html
- Резервный инструмент Stage 3, Songbook и Preview: http://127.0.0.1:8771/index.html

Для приложения не нужны npm, сборка или внешние CDN. Tone.js, WAV, шрифты и SVG локальные. Нужен HTTP-сервер, а не открытие HTML через `file://`.

Резервная `build/demo` пересобрана с теми же тремя звуками, без лишних Nokia-шрифтов и без несуществующей ссылки на новую страницу.

## Удаление NOISE

- Удалены `assets/audio/noise.wav` и `build/demo/assets/audio/noise.wav`.
- В аудиографе загружаются только CALL, PING, CLICK. Их WAV побайтно совпадают с исходными файлами в HEAD: SHA-256 начинаются с `4c128460eda0`, `5f77554179d5`, `e24d6458f025` соответственно.
- Убраны клавиша V, четвёртый pad Stage 3, четвёртые строки RHYTHM, Pad Roll и timeline, соответствующие подсказки.
- `playPad(3)` и `schedulePad(3)` безопасно игнорируются; индекс 3 не переназначается другому звуку. Recorder не записывает удалённый pad, редактор его не создаёт.
- В историческом JSON партитуры сохранены исходные данные. При нормализации 128 событий NOISE/V становятся паузами. Сохраняются оставшиеся 179 ритмических событий на исходных beat-позициях, 170 мелодических событий, 52 такта и 120 секунд. Preview и Songbook используют эту нормализованную партитуру.
- Исторический готовый MP3-микс не может очищаться фильтрацией JSON. Его файлы сохранены как архив, но выбор REFERENCE убран из Preview, а прямой запрос такого воспроизведения блокируется. Рабочий PLAYABLE Preview проигрывает очищенную партитуру через три настоящих сэмпла.
- При чтении сохранённых репетиций версий 1–4 удалённые события фильтруются без сдвига времени, без изменения длины лупа и без переиндексации CALL/PING/CLICK.

Слово NOISE остаётся только в исторических исходных данных, описании миграции и тестах удаления, а не в музыкальных контролах.

## Дизайн

Источник: [SIGNAL SNAKE — Nokia UI / LIVE CONTROLS v2](https://www.figma.com/design/sh7q3C0ABcDxyzGpPaqRRu/?node-id=37-237), фрейм `37:237`, 1512×900. Через Figma получены high-fidelity design context и эталонный рендер; произвольный редизайн не выполнялся.

Корпус, bevel, LCD, клавиши, сетка, STORY MODE и LIVE CONTROLS реализованы HTML/CSS. Семь SVG из Figma сохранены в `assets/nokia/`: два фоновых элемента, четыре стрелки и значок мелодии. SVG используются в соответствующих местах с исходными размерами, временных Figma URL в приложении нет. Шрифты Pixelify Sans, DM Mono и Onest сохранены локально вместе с OFL-лицензиями. Страница не представляет собой растровый скриншот; весь музыкальный интерфейс доступен для редактирования и взаимодействия.

У намеренно функциональных отличий от статического макета есть причина: активная кнопка голоса подсвечивается; READY/LIVE отражает реальный транспорт; стартовая сцена — 01; SIGNAL по умолчанию 0%; скрытая страница останавливается. Удалена вводящая в заблуждение подпись Figma о том, что выбор сцены изменяет паттерн. Добавлены MUTE RHYTHM, доступ к резервным страницам и пояснение о ручном исполнении.

## Работающие контролы

| Элемент | Поведение |
| --- | --- |
| CONNECT | Запускает текущие сетки с первого шага, 104 BPM |
| END CALL / Escape | Останавливает транспорт и освобождает звучащие и будущие события; доступен и после ручного PING |
| MELODY | Сетка 4×8: G4, B♭4, C5, E♭5. Одна нота в столбце, повторный клик удаляет |
| RHYTHM | Сетка 3×8: CALL, PING, CLICK. Несколько сигналов на одном шаге |
| MUTE RHYTHM | Убирает ритмический слой с хвостами, сохраняя рисунок и мелодию |
| Центральная PING | Ровно один ручной PING. Не запускает транспорт, не записывает событие в сетку |
| PITCH | Целые −2…+2 ступени по согласованной C–E♭–F–G–B♭ с переходом октав |
| SIGNAL | Существующий общий аудиоэффект Stage 01, 0–100%, с исходным плавным ramp |
| Физическая SIGNAL | Переводит фокус к настоящему регулятору SIGNAL; стрелки клавиатуры меняют его значение |
| Стрелки ↑/↓ телефона | PITCH на одну ступень в заданных пределах |
| Стрелки ←/→ телефона | Предыдущая / следующая сцена руководства |
| STORY MODE | Клик, Enter/Space, стрелки, Home/End: сцена, номер, прогресс и LIVE GUIDE |
| Цифровая клавиатура | Декоративная, не фокусируется и не запускает звук |

Кнопки имеют hover, pressed, focus и выбранные состояния; range-контролы — focus и состояния thumb. Начальная загрузка без звука. Сцены не включают CONNECT и не меняют темп, эффект, высоту, сетку или mute автоматически.

## Архитектура

- `snake-engine.js` остаётся единственной моделью сеток и планировщиком SIGNAL SNAKE на существующем `Tone.getTransport()`.
- PITCH преобразует ноту только при передаче в существующий синтезатор. Рисунок, положение клеток и длительность четверти не меняются. Будущая атака в Tone lookahead пересогласовывается тем же механизмом отменяемых событий, что в Stage 01.
- `snake.js` — общий контроллер аудио и сетки для Nokia и минимальной страницы. Количество строк RHYTHM определяется фактическим банком звуков.
- `snake-story.js` — данные семи сцен и независимая модель Guide, не имеющая доступа к аудио.
- `snake-ui.js` — визуальные состояния Nokia, навигация и подсказки.
- `signal-snake:state` описывает состояние музыкального контроллера. `signal-snake:scenechange` содержит `{ index, number, total, scene, automaticMusic: false }`. Stage 03 может подписаться на явное намерение выбора сцены; сейчас ни один обработчик не запускает музыкальный переход.

Второго транспорта, отдельного sequencer, нового синтезатора или нового аудиоэффекта нет. Между отдельными документами режимы переходят с остановкой и освобождением прежнего аудио.

## Что остаётся следующему этапу

Автоматические музыкальные состояния сцен, пресеты и переходы Stage 03 не реализованы. Выбор сцены — только руководство. Финальный саунд-дизайн и новые звуки не добавлялись.

Сетки по-прежнему не сохраняются после обновления страницы; tempo и gate мелодии фиксированы. Сдвиг PITCH слышен на следующем музыкальном событии и не перезапускает уже звучащую ноту. Правка в последние 5 мс перед атакой применяется на следующем круге, как в Stage 01. Независимые вкладки не синхронизируются. Проверки выполнены в Chrome, без физических мобильных устройств.
