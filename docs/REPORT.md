# RINGTONE MACHINE — Stage 2: Performance-First UX

30 октября 2026. Рабочая папка: `/Users/matveyabramov/Documents/GitHub/ringtone-machine-prototype`.

## Что изменилось

Сценарий записи теперь **R → сыграть → R**, включая запуск со Stop. Обязательный count-in удалён. REC сразу становится FINISH, а второй R немедленно коммитит события. Отмена выделена в отдельные кнопку и клавишу T. Завершение записи больше не заставляет ждать конца четырёхтактового окна.

После успешного дубля выбирается следующая пустая дорожка и появляется подсказка с её клавишами. Новая запись без отдельного R не запускается. Заполненная дорожка показывает RE-RECORD; пустой дубль сохраняет прежнюю фразу.

Главная зона — LOOP RECORDER: крупная кнопка, выделенная дорожка, состояния с пояснениями, длина и прогресс, независимые Mute/Unmute, Cancel и защита Clear двумя нажатиями за три секунды. Защита удаления — часть интерфейса исполнения; она не требует внешних подтверждений.

Первое открытие показывает три шага. R работает прямо из подсказки. HOW TO PLAY / I остаётся доступной всегда и содержит карту управления. Лупы, физические клавиши и SIGNAL можно использовать без одновременных действий мышью. Фокус на слайдере не блокирует музыкальные клавиши; выпадающие списки получают собственный ввод и после выбора возвращают фокус к REC.

## Адаптивная длина

`phraseBars()` определяет конец реальной фразы по note-off, а для ещё удерживаемой ноты — по моменту FINISH. Для пэда учитывается его позиция и один шаг музыкальной сетки; длина WAV не превращается в дополнительный музыкальный такт.

Auto выбирает минимальную вместительную длину: 1 / 2 / 4 такта (2.5 / 5 / 10 секунд при 96 BPM). Начальная пауза входит в фразу, ожидание после последнего note-off не увеличивает Auto. Окончания нот квантуются независимо от начал, минимум — один шаг сетки. Сетки 1/4, 1/8, 1/16 сохранены, по умолчанию 1/8.

Ручной режим фиксирует 1/2/4 такта: можно нажать FINISH раньше, оставив хвостовую тишину. Без раннего FINISH запись завершается на выбранной длине; в Auto ограничение — четыре такта. Удерживаемый живой звук не обрывается при завершении записи: ограничивается только записанное событие.

## Синхронизация и state machine

`loop-engine.js` хранит независимые `bars`, `origin`, `events`, `muted` и незавершённый `take` каждой дорожки. Тики: 192 PPQ, 768 на такт. До завершения дубля прежние события сохраняются, но не воспроизводятся на записываемой дорожке. Cancel возвращает их; FINISH заменяет.

```text
EMPTY / READY / PLAYING / MUTED / QUEUED
    R → RECORDING
          R / лимит → немедленный commit → QUEUED → PLAYING
          T / Stop → прежняя фраза или EMPTY
```

Сохранение событий и начало звучания разделены. После FINISH `origin` выбирается на общей границе такта. Оставляется запас 40 тиков (~130 ms), чтобы не назначать события на границу, которую Web Audio уже обработал с lookahead. Поэтому состояние QUEUED действительно означает готовый луп, ожидающий ближайшую безопасную границу. Во время этого ожидания можно записывать другой слой.

Подсветка лупов очищается при mute, clear и начале перезаписи; запланированные визуальные вспышки отменяются по версии дорожки, поэтому не показывают уже отключённые ноты.

В приложении остаётся ровно один `Transport.scheduleRepeat` с разрешением 1/16. Для каждого тика события выбираются через modulo индивидуальной длины дорожки. Лупы 1/2/4 такта имеют общую сетку и остаются синхронными. Повторная обработка того же тика после быстрого Restart подавляется. Новая запись не создаёт новый callback.

Ручные нажатия вызывают звук независимо от лупов. Повторный keydown при удержании не создаёт второй note-on. Владение одинаковой высотой мышью и клавиатурой сохраняется до отпускания последнего источника. Захватывается и нота, уже удерживаемая в момент R. Stop отменяет черновик, сбрасывает позицию, освобождает источники и отменяет запланированные атаки. После Restart лупы стартуют с начала со своими длинами.

## Аудиограф

`audio.js` **не изменён относительно Stage 1**. Сохранены Live PolySynth, ограниченный пул независимых огибающих для записанных нот, отдельные банки live/loop Sampler для четырёх локальных WAV, независимые голосовые шины и общий SIGNAL с защитой выхода.

SIGNAL по-прежнему управляет high-pass / low-pass, мягкой distortion и vibrato. В тракте нет feedback-delay или накапливающейся реверберации. Аудиопроверки используют настоящие production nodes и Tone.js 15.1.22.

При завершении страницы удаляется Transport callback и освобождаются узлы/буферы. Поздние события Stop/blur после disposal не могут пересоздавать узлы. Остаточный код отсчёта и его синтезатор удалены из приложения.

## Сохранение репетиций

Ключ `ringtone-machine.rehearsal.v1`, версия формата 1. Сохраняются только законченные event data, длины, mute, сетка, режим длины, выбор дорожки, SIGNAL и дата. На частые движения слайдера применяется debounce 220 ms; завершение записи сохраняется сразу. Чтение проверяет версию, длины, диапазоны, типы событий, шаги и количество; повреждённые данные игнорируются.

Загрузка страницы предлагает Restore / Start Fresh, но оставляет дорожки пустыми и не включает транспорт. Restore возвращает данные только по действию пользователя; запуск музыки требует Space или нового R. Новый дубль без Restore начинает собственное живое исполнение и заменяет старое сохранение после первого успешного FINISH. Если localStorage недоступен, запись работает в памяти. Незавершённые дубли не сохраняются.

- **58 браузерных проверок:** настоящий performance flow с клавиатурными событиями, R из onboarding, ранний FINISH, 1/2/4 такта, разные длины вместе, музыкальные интервалы реальных атак, импровизация, SIGNAL с фокусом на слайдере, отмена/замена, быстрые R, 12 Restart, единственный настоящий scheduleRepeat, отсутствие двойных атак, измеренная тишина после Stop, защищённый Clear, Restore без автозапуска, параметры, русский ввод, клавиатура/мышь, адаптивность, Start Fresh, отключённый storage и teardown.
- **9 дополнительных проверок границ/ресурсов:** настоящий четырёхтактовый повтор с интервалом 10 s; автозавершение при удержании на четыре такта; нота, удерживаемая до R; владение одной высотой мышью и клавиатурой; истечение Clear; нативные Web Audio nodes через Chrome DevTools после прогрева и серий Stop/Restart; поздние Stop/blur после disposal.

**Итог: 118/118 проверок пройдены.** После прогрева нативные Web Audio nodes в контрольной серии из 35 Stop/Restart: **134 → 134, прирост 0**. У приложения остаётся один scheduleRepeat; после disposal поздние события не создают новые узлы. На 1280×800 все игровые зоны, включая SIGNAL, помещаются без прокрутки.

Все проверки выполняются на локальном Tone.js в Chrome/macOS; модель — в Node.js. Тестовые фразы находятся только в `tests/` и не загружаются инструментом. Автоматические проверки подтверждают работу времени и звука, а не художественное качество композиции.

## Короткая приёмка

1. Открыть чистый инструмент и нажать R.
2. Сыграть мелодию A–L на 2–4 секунды; повторным R сразу закончить.
3. Убедиться, что фраза имеет 1–2 такта, сохранена, а пустой Loop 2 уже выбран.
4. Не ожидая четырёх тактов, нажать R, сыграть Z X C V и снова нажать R.
5. Импровизировать A–L поверх повторов; менять SIGNAL [ / ], mute Q / W.
6. Завершить Esc. При следующем открытии вернуть свою репетицию через Restore; музыка не должна стартовать без Space.

Полная карта клавиш и инструкция — в [README](../README.md).

## Ограничения

Два фиксированных голоса, одна запись за раз, 96 BPM, только длины 1/2/4. Нет overdub, undo, экспорта, MIDI-импорта, редактора событий или сохранения аудио. Ручной режим ограничивает окно заданной длиной, Auto — четырьмя тактами. Записанное удержание не переносится через конец лупа. До 512 событий в дубле и 32 одновременных записанных мелодических голосов.

QUEUED может ждать примерно до одного такта; непосредственно перед уже запланированной границей запас планирования может добавить до ~130 ms к такому ожиданию. События при этом уже сохранены, интерфейс доступен для следующего слоя. Mute не восстанавливает пропущенные хвосты; Stop выравнивает начала обоих лупов. Скрытая вкладка останавливается, потеря фокуса отпускает ноты.

localStorage относится к конкретным браузеру и origin/порту; приватный режим и очистка данных сайта могут удалить репетицию. Одна локальная сессия, без истории версий/облачной синхронизации. Другие браузеры отдельно не валидированы. Большие физические аккорды ограничены клавиатурой MacBook.

Финальный Y2K-дизайн не разрабатывался. DUOTONE MINI и старая презентация не редактировались. Commit, push и публикация отсутствуют.
