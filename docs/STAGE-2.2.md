# Stage 2.2 — Full recording and playback audit

Локальная версия RINGTONE MACHINE, 30 октября 2026. Работа ограничена `ringtone-machine-prototype`. Исходный DUOTONE MINI и старая презентация не редактировались. Публикация, commit и push не выполнялись.

## Что действительно было сломано

Причины установлены на предыдущей версии с настоящими клавишами и Tone.js, до внесения исправлений.

| Проверка старой версии | Полученный результат |
| --- | --- |
| A A D F G F D A при обычном старте | 8 raw → 8 saved, 2 bars, 8 DOM-элементов, но только 5 полностью видимых |
| Та же фраза, первый `AudioContext.resume()` возвращается на 2.2 s позже | первые 4 нажатия исчезают; 4 raw → 4 saved, Auto выбирает 1 bar |
| C4 на экране 1280×800 | верх блока около 37 px, высота 3 px, область таймлайна 38 px с бордерами и `overflow:hidden`: блок обрезан |
| Неравномерные интервалы при дефолтной 1/8 | интервалы заменяются кратными 312.5 ms; в воспроизведённом примере отклонение межнотного интервала достигало примерно 114 ms |

**Причина пропусков:** обработчик сначала ждал `ensureAudio()`. Если keyup приходил раньше завершения resume/decode/создания графа, источник удалялся из `held`, а проверка после await просто отбрасывала его. Raw recorder вообще не узнавал об этой ноте. Начало записи визуально показывалось раньше готовности аудио; время ещё не стартовавшего Transport возвращалось как ноль. После запуска оставшиеся события отсчитывались от позднего нуля. Auto не видел всей физической фразы и закономерно выбирал слишком короткий цикл по остаткам.

**Причина ритмического отличия:** включённая по умолчанию музыкальная сетка. Исправление длительности в Stage 2.1 не отменяло сдвиги onset. Они меняли интервалы, а быстрые одинаковые ноты могли оказаться на одной позиции.

**Причина исчезновения в интерфейсе:** нижняя строка C4 не помещалась в компактный CSS-height. Это отдельный дефект: при 8 сохранённых событиях три A всё равно были обрезаны. Повторения с одинаковым квантованным onset также перекрывались визуально.

Плюс прежний playback делал точечный lookup только в тиках 1/16. Простое добавление OFF к селектору не решило бы проблему: произвольные дробные onset не совпали бы с этими точками. Эта структурная проблема устранена вместе с режимом OFF.

Без исходного event store конкретного пользовательского скриншота нельзя определить, сколько нот потерялось именно в нём. Отдельно воспроизведены и потеря на захвате, и обрезание уже сохранённых блоков; они больше не смешиваются в одну гипотезу.

## Новый timing pipeline

| Этап | Время и нулевая точка | Что происходит |
| --- | --- | --- |
| Physical keydown/keyup | DOM-события; монотонный `performance.now()` | Repeat игнорируется, реальные повторные нажатия остаются отдельными |
| R → начало дубля | один `performance.now()` в обработчике R | Этот момент — единственный ноль записи |
| Raw capture | `(inputPerformanceTime − recordingOrigin) / secondsPerTick` | Синхронно, **до любого await**; не зависит от готовности AudioContext/Transport |
| Live voice | `Tone.immediate()` | Немедленный звук при готовом аудио; oscillator/ADSR/velocity прежние |
| Note-off | та же шкала performance, тот же ноль | Raw up фиксируется даже если звук ещё не мог включиться |
| Normalization | raw down − take.start, один раз | Никакого второго вычитания Transport-start или переноса ранних нот в конец |
| Quantization OFF | дробные относительные тики без округления | Onset и положительный gate сохраняются как сыграны |
| Quantization ON | 1/4, 1/8, 1/16 только по выбору | Меняется только onset; gate не округляется |
| Auto length | максимальный onset + gate по **всей** фразе | Только 1/2/4 bars; ведущая пауза также учитывается |
| Saved store | относительные `tick`, `duration`, pitch/pad | Все raw события преобразуются по одному; даже onset и Finish с одинаковой меткой не отбрасываются |
| Loop origin | абсолютные тики глобального Transport | Следующая безопасная граница такта после уже запланированного горизонта |
| Scheduling | полуоткрытые окна `[from, to)` | Все события окна, включая дробные OFF-onset, назначаются ровно один раз |
| Native playback | `windowAudioTime + offsetWithinWindow × secondsPerTick` | Сохраняется относительный ритм; общий сдвиг нужен только для запуска на границе |
| Timeline | **те же saved events**, та же длина цикла | Один `.event` на событие, позиция и ширина из реальных tick/duration |

Фиксировано 96 BPM: 192 тика на четверть, `secondsPerTick = 0.625 / 192`. Один такт 768 тиков / 2.5 s, два — 5 s, четыре — 10 s. Performance clock не используется как абсолютное аудиовремя: он даёт только относительные интервалы внутри дубля. Один явный перевод в тики хранится в recorder, обратный перевод в секунды используется при playback. Отдельная эпоха AudioContext не вычитается из времени входа.

Для сохранённых лупов остаётся один `Transport.scheduleRepeat` с окнами 1/16, но это **частота вызова планировщика, не сетка квантования**. Внутри окна ноты могут начинаться в любой дробной позиции. Ровно одно окно владеет каждым onset; индекс события и номер итерации позволяют проверить отсутствие дублей.

Transport получает 100 ms lookahead для запаса при задержках UI/worker. Ручные клавиши используют `Tone.immediate()`, а не этот буфер, поэтому увеличение запаса не добавляет ручной игре 100 ms задержки. Finish выбирает ближайший такт **за реально запланированным горизонтом**, а не за произвольно добавленным сдвигом к нотам. Сохранён защитный запас 40 тиков (~130 ms) у границы; он может пропустить слишком близкий такт, но не меняет относительные времена нот. QUEUED сообщает о таком ожидании; следующая дорожка доступна сразу.

## Первое включение звука

Буферы и граф готовятся заранее в тишине. Transport и ноты от подготовки сами не запускаются. Существующая кнопка «Понятно, закрыть» в onboarding включает аудио перед закрытием, чтобы обычная ручная игра начиналась с готовым устройством. R из onboarding по-прежнему сразу начинает запись.

Если браузер/устройство ещё не готово, UI прямо показывает подготовку, но **все нажатия уже сохраняются**. Удержанные клавиши запускаются по реальному `statechange` AudioContext, без ожидания запоздалого Promise resume. Уже отпущенная клавиша не «воскресает» позже. Finish, второй R и второй слой корректны даже до окончания decode.

Физически воспроизвести звук до разрешения/готовности AudioContext невозможно. Такие начальные нажатия теперь сохраняются, но могут быть не слышны в ручной игре до готовности. Для сравнения ручного звука с playback в пределах 30 ms устройство должно быть готово — это отдельно проверяется, а не скрывается общей статистикой. Не нужно вручную запускать Transport: достаточно дождаться окончания надписи о включении звука.

## Длина, границы и ограничения

Auto включает всю фразу от R до последнего note-off. На примере восьми четвертей получается 2 bars, а не 1. Отсутствие нот в начале больше не может сократить расчёт из-за позднего старта аудио. При OFF начальные паузы и все межнотные интервалы остаются неизменными.

В ручном режиме прямо показано FIXED и 2.5/5/10 s. В Auto показан предел 4 bars / 10 s. По достижении предела дубль завершается, появляется постоянное пояснение, что дальнейшая игра уже не записывается. Следующий слой не начинает записываться сам. Лимит 512 событий тоже имеет явное сообщение.

Finish закрывает ещё удерживаемую записанную ноту в момент Finish, а живая нота остаётся до keyup. Положительные очень короткие gate не округляются. Только событие нулевой длительности в одной метке clock получает технический gate 1 ms, чтобы оно не исчезло. Хвост через границу сохраняется отдельной огибающей; Stop/mute освобождают и такие голоса.

## Таймлайн

- Исправлена высота для всех девяти высот, включая C4 в компактном режиме.
- `8 NOTES` / `4 HITS` показывают реальный размер event store; при записи — raw count текущего дубля.
- Каждый saved event имеет свой `.event` и `data-index/tick/duration/value`. Группировки или объединения одинаковых высот нет.
- При совпадающих/перекрывающихся событиях одной высоты используются разные подстроки; границы блоков отделены контрастным бордером. В очень плотной записи таймлайн можно прокрутить по вертикали.
- Для перехода через край у одного логического события рисуются head/tail сегменты. Это **не две ноты**; логический DOM count остаётся равен saved count.
- Ширина ноты соответствует gate, а не Release. Шкала имеет фактическую длину 1/2/4 bars. В режиме фиксированной записи preview также соответствует фиксированной длине.

## Формат и диагностика

Сохранения version 3 поддерживают OFF и дробные onset. Version 1/2 по-прежнему читаются. Из старых уже квантованных записей нельзя восстановить потерянную экспрессию; для оценки новой версии их нужно сыграть заново. Restore не запускает музыку автоматически.

`?diagnostics=1` добавляет к read-only snapshot аудит последнего дубля: raw count, saved count, start/end и сырые down/up. Эти данные не сохраняются в репетицию и не печатаются в обычный UI/console. Нормальная игровая страница не содержит тестовых партий.

## Проверки и доказательства

Основной runner — `tests/fidelity-browser.test.cjs`. Он играет фразы через **настоящие `page.keyboard.down/up`**, использует production state machine и Tone.js. Прямое заполнение массива нот не подменяет E2E.

Сценарии:

- A: A A D F | G F D A — первый луп, уже работающий Transport, задержанный resume и неравномерные интервалы;
- B: в одном дубле удержания 150/300/500/1000/1500 ms;
- C: первая нота сразу и через 500 ms, быстрые A A, аккорды, Finish при удержании, конец 1 bar, фразы на 2/4 bars, предел 10 s;
- D: запись пэдов поверх мелодии, разные длины, mute/unmute, Stop/Restart, Cancel, re-record и Restore;
- E: raw/saved/scheduled/DOM counts и геометрия видимости каждого блока.

Для сценария A дополнительно записывается **фактический выход production Web Audio** через MediaStreamDestination/MediaRecorder и декодируется в PCM WAV. Анализируется один музыкальный цикл, выбранный по его известному origin/длине: из него исключены последний ручной Release перед циклом и уже буферизованное начало следующей итерации. Это выделение диапазона аудиозаписи в тесте, а не изменение событий приложения.

В PCM считаются отдельные атаки по огибающей RMS (20 ms окно, 10 ms шаг); сравниваются относительные интервалы, исключая только общий сдвиг начала. Длительность gate независимо сверяется по физическому keyup, saved duration и native Tone.js note-off. ADSR/осциллятор/громкость ручного и записанного инструментов сравниваются во время реальных вызовов.

**Финальный результат:** 109 сквозных E2E-проверок A–E, 58 общих браузерных регрессий, 30 gate/CALL E2E, 9 граничных/ресурсных, 8 визуальных граничных, 67 проверок модели и 81 аудиопроверка с настоящим Tone.js — всего **362 проверки пройдены**.

В сценариях A все количества 8 → 8 → 8 → 8, длина 2 bars. Максимальная ошибка сохранённых/запланированных интервалов — 0.2 ms; максимальная ошибка реальных аудиоатак — **5.5 ms для ровной** и **4.2 ms для неравномерной** фразы. Предел цели 20–30 ms не превышен в финальном прогоне. На выходе действительно восемь отдельных атак. Повторения не добавляют и не пропускают ноты.

Проверены 150/300/500/1000/1500 ms на OFF/1/4/1/8/1/16 через production audio graph; waveform совпадает с независимым известным gate, Release отделён от удержания. CALL остаётся одноатакным при SIGNAL 0/0.5/1, остальные WAV неизменны. После прогрева контрольные 35 Stop/Restart дают нативные аудиоузлы **134 → 134**, callback остаётся один, после Stop — измеренная тишина.

Старый тест удержания до R также исправлен: после автоперехода он раньше мог проверить старую ноту другой дорожки. Теперь он явно выбирает Loop 1, записывает другую высоту и проверяет новые данные. Повышение количества тестов само по себе не принято за доказательство: основной результат подтверждён PCM-записью и соответствием всей цепочки.

Артефакты сценария A, точные числа и результаты финального прогона приведены в [SCENARIO-A.md](SCENARIO-A.md).

## Проверка человеком за 30 секунд

1. Обнови вкладку, нажми Start Fresh. Убедись: **OFF**, **Auto**, обе дорожки пусты. Если звук ещё включается — дождись готовности.
2. Нажми R и сыграй **A A D F | G F D A** примерно по одной ноте на каждую долю: вся фраза около пяти секунд. Заверши R.
3. У Loop 1 должны быть **2 BARS** и **8 NOTES**, на таймлайне — восемь различимых блоков, включая три A. В повторе должны сохраниться ритм и удержания.
4. Сразу R → Z X C → R для второго слоя. Поиграй поверх лупов, нажми Q/W и [ / ]. Закончи Esc.

Ограничения: максимум 4 bars / 10 s и 512 событий в дубле, 32 одновременно звучащие записанные мелодические голоса; после превышения полифонии UI сообщает об этом. Нет overdub/undo/экспорта/облачного сохранения. Скрытая вкладка останавливается. Проверки проведены в Chrome/macOS; запуск на аудиоустройстве/вкладке, ещё не получивших разрешение на звук, не может иметь нулевую задержку. OFF не исправляет исторические уже квантованные записи.
