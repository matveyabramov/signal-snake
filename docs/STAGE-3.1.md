# Stage 3.1 — Editable Piano Roll

Прототип: `http://127.0.0.1:8767/`.
Папка: `/Users/matveyabramov/Documents/GitHub/ringtone-machine-prototype`.

## Редактирование за полминуты

1. В **PERFORM** запиши короткую фразу обычным способом **R → игра → R**. Сетка автоматически покажет законченный луп, даже когда для следующей записи уже выбран Loop 2.
2. В панели **PIANO ROLL** нажми **EDIT**. Эта кнопка есть и в верхнем переключателе режимов. Выбери **Voice A · Loop 1** или **Voice B · Loop 2**.
3. Нажми пустую клетку — добавится одно событие. Нажми блок — он выделится. Перетаскивай влево/вправо для изменения начала, вверх/вниз — для изменения высоты или пэда.
4. У мелодической ноты потяни **правый край** для изменения удержания. Пэды однократные: у них нет растягивания, не влияющего на звук.
5. **Delete / Backspace** или кнопка **Удалить** удаляет только выбранный блок. После Undo выбери восстановленный блок заново, прежде чем удалять или двигать его.
6. **⌘Z / Ctrl+Z** или **Undo** отменяет последнюю правку текущего лупа. **Слушать / Пауза**, либо Space, управляет настоящим транспортом обоих лупов. Вернись в **PERFORM / Готово**, чтобы защитить сетку от случайных касаний.

Латинские буквы обозначают физические позиции клавиш MacBook. Для основных операций правая кнопка мыши и сложные сочетания не нужны.

## Сетка и длительности

Вертикаль — высота ноты, горизонталь — время. Слева видны девять нот и их клавиши; высокие ноты находятся сверху:

| Нота | Клавиша |
|---|---|
| G5 | L |
| F5 | K |
| E♭5 | J |
| C5 | H |
| B♭4 | G |
| G4 | F |
| F4 | D |
| E♭4 | S |
| C4 | A |

В текущем SIGNAL SNAKE Stage 02 у Voice B три строки: CALL/Z, PING/X, CLICK/C. Исторический NOISE/V удалён. Клавиша, реально удерживаемая пользователем, подсвечивает соответствующую строку. Подсветка лупа не выдаётся за нажатие человека.

- **Длина лупа:** 1 / 2 / 4 такта, соответственно 2.5 / 5 / 10 секунд при 96 BPM. Это длина текущего сохранённого лупа; верхняя настройка Auto/1/2/4 по-прежнему относится к новой записи.
- **Snap:** OFF / 1/4 / 1/8 / 1/16. По умолчанию редактор предлагает 1/8; обычная запись сохраняет свой прежний default OFF. Эти две настройки независимы. Переключение Snap само по себе не меняет ни одной ноты.
- При переносе горизонтально округляется начало. Чисто вертикальный перенос сохраняет дробное исходное время, даже при включённом Snap. Удержание при переносе не меняется. При растягивании правый край явно привязывается к выбранной сетке.
- Новая нота получает удержание, равное текущему шагу Snap; при OFF — 1/8. Минимум при ручном растягивании — **20 мс**, максимум — 10 секунд. Существующие записанные удержания, даже меньше 20 мс, не округляются и не удлиняются автоматически.
- Ноту можно удерживать за границей лупа. Её хвост показан пунктиром в начале шкалы и указан в подсказке. Удержание не обрезается. Потяни основной блок для переноса; пунктирный хвост выбирает исходную ноту. Правый край меняет полную длительность, включая хвост.
- Уменьшение длины, при котором начала событий окажутся за границей, **отклоняется с объяснением**. Ни одно событие молча не удаляется. Сначала перенеси/удали поздние события; длительные хвосты могут оставаться через границу.
- Каждая нота имеет отдельный блок. Перекрывающиеся ноты одной высоты и близкие короткие события размещаются на отдельных уровнях внутри своей строки. Нет группировки, слияния или потери повторных нажатий.
- **Масштаб Fit · ×1 / ×2 / ×4 / ×8** приближает время. После записи редактор возвращается в Fit и к началу шкалы, чтобы показать всю фразу. Горизонтальная прокрутка работает внутри сетки трекпадом. При плотной фразе доступна вертикальная прокрутка. Подписи строк и линейка закреплены. Tooltip и нижняя строка показывают имя, onset в секундах и удержание в миллисекундах.

## Как применяются правки

Единственное постоянное хранилище музыкальных событий — `Recorder.tracks[index].events`. Piano Roll читает его; обычные обзоры дорожек, сохранение и проигрывание используют те же события. Во время жеста есть только временный preview: отпускание мыши коммитит одну правку, а отмена/потеря фокуса его отбрасывает.

Когда транспорт остановлен, правка применяется сразу. Во время игры:

1. Новые события немедленно становятся канонической версией и сохраняются в localStorage по прежнему формату v3.
2. Только для завершения текущего цикла остаётся неизменяемый снимок прежнего score.
3. Граница применения считается относительно исходного `origin` и **прежней длины лупа**, за горизонтом уже запланированных Transport-окон с прежним защитным запасом 40 ticks. Все границы кратны тактам.
4. До этой границы `eventsBetween` читает прежний score; после неё — новые канонические данные с `origin` на этой же границе. Так как бар кратен шагу единственного существующего scheduler, промежуточное окно не пересекает переключение версий.
5. **EDIT QUEUED** и обратный отсчёт явно сообщают, что прежний цикл доигрывает. Сетка уже показывает будущую версию; её playhead начинает новый цикл при применении. Несколько последовательных правок и Undo до применения используют ту же границу.

Уже прозвучавшие ноты заканчивают свои огибающие. Они не retrigger-ятся при правке. Новые ноты используют существующий ограниченный пул независимых synth voices; Voice B — существующий Sampler bank. Нет второго транспорта, нового аудиографа или дополнительных музыкальных callbacks. Мьют учитывается и для прежнего снимка. Stop применяет актуальное содержимое без ожидающей версии; Restart играет актуальные events с начала.

Clear отменяет ожидающую версию и её будущий звук. Начало новой записи также отменяет редакторский preview/ожидание для этой дорожки, защищая capture. Проверка revision не позволяет позднему pointerup перезаписать новый дубль или восстановленную сессию. Геометрия строк фиксируется на время жеста: изменения высоты занятой строки не меняют случайно выбранную высоту ноты.

Undo ограничен 50 правками на дорожку; события/длины восстанавливаются вместе. История не включает живую запись, Mute и SIGNAL и сбрасывается при новом дубле, Clear, Start Fresh, Restore и смене учебной сессии. Redo не добавлен.

## Performance и Practice

PERFORM/EDIT — независимый переключатель от Учиться/Играть. В PERFORM ноты видны, но мышь не может их изменить. В EDIT настоящие музыкальные клавиши, R, Q/W, SIGNAL и транспорт продолжают работать. Backspace/Delete и ⌘Z перехватываются редактором, чтобы не сработало случайное удаление целого лупа. В полях/меню они сохраняют обычное поведение.

Во время записи отключено редактирование **этого лупа**, включая Undo и длину; другую дорожку можно править. Завершение показывает все действительно сохранённые события. Кнопки выбора голоса в редакторе переключают просмотр, не меняя выбранную для R дорожку. Клавиши 1/2 по-прежнему выбирают дорожку для записи и одновременно переключают просмотр.

Practice использует прежнюю временную сессию. Её events можно редактировать в EDIT, но эти изменения не записываются поверх Performance localStorage. Выход возвращает исходное исполнение. Редакторские действия не выдаются за исполнение урока: они не отправляют фиктивные input/record/commit события и не улучшают оценку исходных нажатий.

## Проверки

Все браузерные сценарии выполнялись в изолированном Chrome с настоящим локальным Tone.js 15.1.22. Ноты в приложении создавались настоящими pointer/keyboard событиями, а не внедрением тестовых score-массивов.

- **24** проверки `tests/roll.test.cjs`: дробные onset/gate, OFF и все Snap, положительный минимум, хвосты, валидация длины, прежний score и однократность scheduler windows.
- **61** проверка `tests/roll-browser.test.cjs`: полный путь пустая сетка → mouse insert/select/drag/resize/delete/Undo → save/reload/Restore → воспроизведение исправлений настоящим Tone → запись во время EDIT → Practice → возврат к PERFORM. Проверяются все сохранённые DOM-события, короткие повторы, аккорды, границы, 1/2/4 такта и масштаб.
- **21** проверка `tests/roll-edges.test.cjs`: настоящие Sampler-триггеры после переноса/смены пэда, 1-bar + 4-bar слои, очередь длины, Mute/Stop/Restart/Clear, отмена жеста началом записи, перекрывающиеся строки, 50-step Undo bound, повторные mouse edits и native Web Audio resources, мобильный overflow.
- **109** прежних full-pipeline проверок записи/проигрывания прошли с новым редактором. A A D F | G F D A: физические 8 → raw 8 → saved 8 → scheduled 8 → timeline 8, Auto 2 bars. Измеренные относительные интервалы в PCM отличались от вводимых на 2.9 мс (ровная фраза) и 5.3 мс (выразительная).
- **55 + 21** прежних browser-проверок четырёх уроков и границ Practice прошли с Piano Roll, включая сохранение Performance, позднее отпускание и удаление учебных аудиоузлов.
- **97** прежних unit-проверок recorder/duration/fidelity/practice также прошли.

Для живой правки записан реальный AudioContext output за два цикла. Старый цикл имел onset 0 / 384 ticks, новый — 0 / 480 ticks. Вызовы synth: абсолютные ticks **0, 384, 768, 1248**. Четыре слышимые атаки в PCM, без промежуточной ноты; расхождение интервалов — **2.5 мс**. Пэды независимо проверены сопоставлением каждого loop event с ровно одним настоящим Sampler trigger.

Всего **388 успешных проверок**: 82 новых browser-проверки редактора, 24 новых model-проверки и 282 регрессионных. В двух равных сериях повторных правок число native Web Audio nodes: **134 → 134**, единственный Transport scheduler сохранён.

Подробные JSON и screenshots находятся в `docs/roll-validation/`. Аудиофайл `live-edit-playback.wav` — только результат QA, он нигде не загружается инструментом.

## Ограничения и ручная проверка

- Живая правка слышна со следующей безопасной границы **старого** лупа. Для четырёх тактов ожидание может составить примерно 10 секунд; при попадании в уже запланированную границу используется следующая. Можно Stop → Слушать, чтобы начать актуальную версию сразу с начала.
- Уменьшение длины не переносит и не удаляет поздние ноты за пользователя; необходимо исправить их явно. Хвосты сохраняются.
- Нет Redo, multi-select, копирования, произвольного звукоряда, velocity editor или автопрокрутки при drag за видимый край. Для дальнего переноса уменьши масштаб, затем приблизь снова. Это компактный редактор двух лупов, не DAW.
- История Undo и учебные партии не сохраняются после обновления, сами исправленные Performance events сохраняются. Есть прежний лимит 512 событий и 32 одновременно звучащих мелодических loop voices.
- Автоматическая проверка проводилась в Chrome. На физическом MacBook вручную проверь удобство правого края короткой ноты при ×4/×8, горизонтальную прокрутку трекпадом, комфорт задержки звука в своих наушниках и работу Safari, если используешь его.

DUOTONE MINI, старая презентация, Tone.js, аудиограф и исходные WAV-файлы не изменялись. Commit/push/публикация не выполнялись.
